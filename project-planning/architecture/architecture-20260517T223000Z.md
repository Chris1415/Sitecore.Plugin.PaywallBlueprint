## 1. Architecture Overview

PRD-002 is a **UI-shell delta** on top of the shipped paywall-blueprint product (PRD-000 foundation + PRD-001 Stripe integration, both live at `https://sitecore-plugin-paywall-blueprint.vercel.app/`). The entire monetization spine — `MarketplaceProvider`, `useEntitlement` (postMessage + 60s polling + visibility-refresh), `PaywallCheckoutDialog`, `/paywall-return`, the `/api/checkout` / `/api/entitlement` / `/api/webhooks/stripe` routes, the `SupabaseStore`, the `StripeProvider`, the entitlement evaluator, ADR-0011 tenant-only gating — carries through **unchanged**.

What changes: `/full-page`'s rendered content. The current `<FreeSection> + <Separator> + <GatedSectionWithDevPicker>` composition is replaced by a single `<BentoGrid>` shell that orchestrates 11 cards (5 free, 6 premium) under one CSS grid. The free row binds to real APIs (`host.user`, `application.context`, `xmc.sites.listSites`, `SupabaseStore`). The premium row binds to **hardcoded fake data** per ADR-0018 — no fetches, no SDK calls, no database queries at any state. Locked-state premium cards mount as skeleton silhouettes wrapped in `filter: blur(12px) opacity(0.7) pointer-events:none` with a centered Subscribe banner; unlocked-state premium cards render the fake-data content with a stagger-in cascade and Recharts area chart (lazy-loaded).

Three smaller deltas accompany the bento shell:
1. A **theme system** — `<ThemeProvider>` from `next-themes` at root layout + `<ThemeToggle>` in the Topbar's `rightSideItems[]` (always visible per ADR-0016).
2. A **schema migration** — `processed_events.tenant_id TEXT` column (ADR-0017) — for F4's per-tenant filtering. One-line webhook handler update writes the column.
3. A **Recharts lazy-load contract** — premium-only chunk; free-tier first paint must not pay the ~80–100kb gzipped Recharts cost (NFR-1).

**No new API routes ship in PRD-002.** F4 reads `processed_events` via server-render (RSC fetch through the existing `SupabaseStore`); F2 uses the existing Mode A `client.query('xmc.sites.listSites')` postMessage path. The architecture is intentionally additive — no new infrastructure, no new auth surface, no new env vars.

**Architecture inheritance from PRD-000/001 (binding, do not re-design):**

- App architecture **4b — Full-stack Marketplace** (Mode A iframe + own API routes for webhook + own data layer; ADR-0013)
- `xmc:fullscreen` extension point at `/full-page`; bound to one tenant
- Tenant-only entitlement via `application.context.marketplaceAppTenantId` (ADR-0011)
- Supabase row-level security with permissive default policies (ADR-0009); service-role key server-only (NFR-7/NFR-8)
- `MarketplaceProvider` resolution as context-readiness signal (ADR-0008)
- Iframe success-return via postMessage primary + 3s/30s polling fallback (ADR-0014)

## 4. Data Model

### 4a. Supabase — one additive schema change (ADR-0017)

**Existing tables unchanged:**

- `tenants` — read by `SupabaseStore.getEntitlement(tenantId, '')` in F3. No schema change. Read by RSC at `/full-page/page.tsx`.

**Modified table:**

```sql
-- processed_events: add tenant_id column for per-tenant filtering (F4)
ALTER TABLE processed_events
  ADD COLUMN tenant_id TEXT;

-- Optional backfill (skip if too complex; accept NULLs as legacy data):
-- UPDATE processed_events pe
--   SET tenant_id = t.tenant_id
--   FROM tenants t
--   WHERE t.stripe_customer_id = (pe.event_data ->> 'customer')::text;
```

- **Column nullable** — pre-migration rows stay NULL; new rows from PRD-002 onwards have populated `tenant_id` from the Stripe Checkout Session `metadata.tenant_id`.
- **No index needed at v1** — `tenant_id` filter cardinality is low (single tenant in F4 query) but the table itself stays small (idempotency cache); add a `CREATE INDEX IF NOT EXISTS idx_processed_events_tenant_id ON processed_events (tenant_id, processed_at DESC);` later if F4 latency becomes a concern.

**New query method on `SupabaseStore`:**

```typescript
async getRecentEventsForTenant(
  tenantId: string,
  limit = 5,
): Promise<Array<{ event_id: string; processed_at: string; event_type: string | null }>> {
  const { data, error } = await this.client
    .from('processed_events')
    .select('event_id, processed_at, event_type')
    .eq('tenant_id', tenantId)
    .order('processed_at', { ascending: false })
    .limit(limit);
  if (error) throw error;
  return data ?? [];
}
```

> **Note on `event_type` column.** If the existing schema does NOT carry `event_type`, drop the column from the select and have F4 render only `event_id` + relative time. Verify in Tranche A; this is a small drift point and a smoke item for Gate A.

### 4b. Stripe — no changes

PRD-002 makes zero new Stripe API calls. Premium tier is fake (ADR-0018). The webhook handler change is one line inside an existing insert — no new event types are subscribed.

### 4c. Marketplace SDK — one new query

`client.query('xmc.sites.listSites', { params: { query: { sitecoreContextId } } })` — Mode A, response double-unwraps to `result.data?.data`. See § 7 for the cited contract.

## 5. API Design

### 5a. No new HTTP routes added in PRD-002

### 5c. Marketplace SDK call surface (PRD-002 free row)

```typescript
// site/components/bento/sites-tile.tsx (Mode A client component)
'use client';
import { useEffect, useState } from 'react';
import { useMarketplaceClient, useAppContext } from '@/components/providers/marketplace';
import type { Xmapp } from '@sitecore-marketplace-sdk/xmc';

export function SitesTile() {
  const { client } = useMarketplaceClient();
  const appCtx = useAppContext();
  const [state, setState] = useState<
    | { kind: 'loading' }
    | { kind: 'success'; sites: Xmapp.Site[] }
    | { kind: 'empty' }
    | { kind: 'error'; message: string }
  >({ kind: 'loading' });

  useEffect(() => {
    if (!client || !appCtx) return;
    const contextId = appCtx.resourceAccess?.[0]?.context?.live;
    if (!contextId) {
      setState({ kind: 'error', message: 'Sitecore context unavailable' });
      return;
    }
    let cancelled = false;
    (async () => {
      try {
        const result = await client.query('xmc.sites.listSites', {
          params: { query: { sitecoreContextId: contextId } },
        });
        if (cancelled) return;
        const sites = result.data?.data ?? [];  // double-unwrap per § 7
        if (sites.length === 0) setState({ kind: 'empty' });
        else setState({ kind: 'success', sites });
      } catch (err) {
        if (!cancelled) setState({ kind: 'error', message: String(err) });
      }
    })();
    return () => { cancelled = true; };
  }, [client, appCtx]);

  // ... render four states (Skeleton / sites / empty / Retry)
}
```

Notes:
- **No `as never` / `as any` cast** — types resolve through `Xmapp` namespace from `@sitecore-marketplace-sdk/xmc`.
- **`contextId` guarded, not cast** — per `sitecore:marketplace-sdk-xmc` skill § 6a; cast-vs-guard rule is binding.

## 8. Security Considerations

### 8a. Premium DOM exposure under blur (R5a — blueprint posture)

- **Locked state mounts placeholder silhouettes only** (FR-3.1; ADR-0018). No fake data, no real data, no fetches. The blurred DOM contains shape but no extractable content.
- `aria-hidden="true"` on the locked premium region wrapper (FR-6.5; NFR-2). Screen readers skip everything inside except the Subscribe banner.
- `pointer-events: none` on the wrapper. Keyboard tab focus skips locked premium cards.
- Result: no real premium content is exposed in any locked-state mount path. The "render-then-blur" posture is intentional and the shape leak is shape-only.

### 8b. Adopter hardening note (R5b — non-binding contract on the OSS fork audience)

ADR-0018 explicitly delegates production hardening to adopters who swap fake premium cards for real fetches. The README "Production hardening for adopters" subsection (Tranche E) names three requirements:

1. Server-render premium card data behind an `/api/entitlement` check (server-side gate, not client-side).
2. Return empty/null props from the RSC layer if entitlement is `tenant_no_subscription`; never let raw premium data reach the client component, even blurred.
3. Consider a `withEntitlement(handler)` HOF (deferred to a future PRD candidate; named in PRD § 15).

This is documentation, not code in PRD-002. No enforcement mechanism — the blueprint cannot prevent adopter misuse, only warn loudly.

### 8c. Theme toggle accessibility

- Keyboard: `<button>` element with visible `focus-visible:ring-2 focus-visible:ring-ring`. Tab order: after brandName, before TenantIdBadge.
- Screen reader: `aria-label="Toggle theme"` + dropdown items each have explicit text labels (Light / Dark / System).
- Color contrast: every theme-toggle state passes WCAG AA in both light and dark (manual smoke at Tranche D — NFR-2/NFR-6).
- No animation in the toggle itself (theme switch is instant; respects `prefers-reduced-motion: reduce` via CSS).

### 8d. Server-only env vars unchanged

`STRIPE_SECRET_KEY`, `SUPABASE_SECRET_KEY` remain server-only. The existing `npm run test:env-leak` test continues to enforce no `NEXT_PUBLIC_*` leak (NFR-8). PRD-002 adds zero new env vars.

### 8e. Tenant isolation on `processed_events` filter

F4's query (`.eq('tenant_id', tenantId)`) runs server-side with the `tenantId` derived from `application.context.marketplaceAppTenantId` — the same source that gates entitlement (ADR-0011). RLS policies (ADR-0009) are permissive-default in PRD-000; the architecture inherits this trust model. Production adopters tighten RLS per the same R5b contract.

### 8f. CSP / iframe headers unchanged

PRD-000/001 already set the Marketplace-required CSP + cookie config (per `sitecore:marketplace-sdk-testing-debug` skill § 4). PRD-002 introduces no new origins, no new third-party scripts. Recharts is a pure-JS dep with no external CDN. `next-themes` is also pure JS. No header changes.

| ID | Risk | Likelihood | Impact | Mitigation |
|---|---|---|---|---|
| **R-A** | `xmc.sites.listSites` real-tenant response shape diverges from `.d.ts` / skill docs | Low | Medium (F2 card breaks; rest of bento unaffected) | Tranche A capture gate (§ 7b); progressive-fixture-capture is acceptable; F2 has documented error fallback (FR-7.3) |

| **R-C** | Stagger-in animation jank on low-end hardware | Low | Low | CSS keyframes are GPU-accelerated; `prefers-reduced-motion: reduce` covers the long tail (NFR-5) |
| **R-D** | Theme toggle exposes existing hard-coded hex elsewhere in the app | Medium | Low | `test:no-hex-in-bento` covers new code; manual visual smoke at Tranche D in both themes catches cross-component drift; fix-as-found policy |
| **R-E** | Theme toggle policy departure (ADR-0016) confuses adopters | Low | Low | ADR-0016 explicit; README "Production hardening for adopters" section names the divergence and the env-gate pattern adopters should adopt |
| **R-F** | `processed_events` schema migration not applied before code deploy → F4 crashes on missing column | Medium | Medium (full-page crashes on F4 server-render) | Tranche A operator gate verifies the migration before Tranche B code lands. | **R-G** | `processed_events.event_type` column does not exist in current schema (only `event_id` + `processed_at`) | Medium | Low | Tranche A schema inspection step (§ 4a note); if absent, F4 renders only `event_id` + relative time. Operator smoke catches at Gate A. |

| **R-I** | Adopter forks blueprint, swaps fake premium for real fetches, ships without server-side gating → real-content leak through blur (R5b) | High (eventual) | Out of scope — adopter responsibility | README hardening section + ADR-0018 + R5b PRD note are the only mitigations. | **R-J** | `<ThemeToggle>` hydration mismatch — server renders one icon, client renders another | Low | Low | `mounted` guard pattern (next-themes canonical) + lesson from `feedback_hydration_mismatch_pattern.md`; renders neutral icon (or `null`) until `useEffect` sets `mounted=true` |
| **R-K** | `--primary-foreground` collapses onto `--primary` in dark mode → Subscribe banner CTA unreadable | Low | Medium (CTA goes invisible) | Verified in `sitecore:blok-theming` skill pitfall section; bento contract prefers `text-background` for primary buttons until the pair is confirmed safe; manual smoke at Tranche D in both themes |

### Tradeoffs surfaced explicitly

- **Fake premium vs real signals.** Pure showcase posture; adopter must wire production data themselves. Accepts that the OSS blueprint is less "useful out of the box" in exchange for zero big unknowns in PRD-002 (operator direction; ADR-0018).
- **No new API routes.** F4 is server-rendered, not behind a dedicated `/api/activity`. Simpler scope; loses cache-control nuance and per-card refresh capability. Accept — bento is page-load-fetched-once (NFR-3).
- **Always-visible theme toggle.** Policy departure (ADR-0016). Trade portfolio consistency for blueprint showcase polish.
- **CSS animations vs animation library.** No `framer-motion` / `motion`. Trade convenience APIs for zero added bundle weight and full `prefers-reduced-motion` control.
- **Card components hold no fetches (NFR-10).** Layout shell `<BentoGrid>` is the single fetch-orchestration point. Trade reusability surface (adopters can't drop a card into another page without rewiring data) for prop-clarity and adopter swap pattern simplicity.
