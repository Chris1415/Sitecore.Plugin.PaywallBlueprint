## 1. Executive Summary

Replace `/full-page`'s current freemium demo with a **bento-grid dashboard** that puts the paywall-blueprint's monetization story on its strongest visual footing. Five always-visible free cards present **real data from APIs we already know** (welcome / sites count / plan + member-since / user profile / tenant info). Six premium cards sit behind a `filter: blur(12px) opacity(0.7)` + centered Subscribe banner; once the user pays €0.99 and the iframe reloads, the cards reveal in a ~600ms stagger-in cascade. **All premium cards are pure marketing — Sitecore-flavored fake data, beautiful animations, no API fetches.** The premium tier exists to demonstrate the visual story of "look what unlocks", not to surface load-bearing data signals.

The freemium plumbing from PRD-001 — Stripe Checkout, the webhook handler, `useEntitlement` with its visibility-refresh + 60s polling, the `PaywallCheckoutDialog`, the `/paywall-return` page — carries through **unchanged**. PRD-002 adds: new bento components, one new Marketplace SDK call (`xmc.sites.listSites`), a topbar theme toggle (light / dark / system), and the bento composition itself. **No schema migrations, no new API routes, no webhook handler changes.** The shipped winning variant is v2 — Editorial Cadence (asymmetric masonry; see `project-planning/ui-design/ui-design-20260517T223000Z-v2.md` § 7 + `pocs/poc-v2-prd002/`).

This PRD's value to adopters: **the OSS blueprint becomes a much stronger marketing surface**. Anyone forking this for their own Marketplace monetization sees a polished dashboard, not just a working gate. The free-vs-premium split is visible at a glance instead of being explained. Adopters who fork later add their own real data behind the premium cards as production-hardening (R5b).

## 2. Problem Statement

PRD-001 made the paywall flow *work* — real €0.99 Stripe Checkout, real webhook, real entitlement gating. The freemium *demonstration* is functional but visually flat: a single "free section" with placeholder copy above a separator above a single welcome card. Adopters reading the README can grasp the pattern, but the **visual story** of "here's what you get for free, here's what you unlock with premium" doesn't land — there's only one premium thing (the welcome card with user identity), and it competes with the placeholder free content for attention.

A blueprint adopter cloning this repo today inherits working plumbing but a tepid showcase. PRD-002 fixes the showcase. The freemium pattern becomes a dashboard composition that adopters can swap card-by-card with their own data signals — items, sites, activity, anything their app actually has — and the visual rhythm of "5 free + 6 blurred premium → unlock → 6 premium revealed" makes the value proposition self-explanatory.

Secondary problem: the current `/full-page` doesn't surface any Sitecore-specific data. The app is a Sitecore Marketplace App, but its dashboard tells you nothing about your Sitecore tenant beyond your name. PRD-002 adds `xmc.sites.listSites` to the free tier as a small, verified Sitecore signal — demonstrating the SDK pattern adopters will reuse. Deeper Sitecore content queries (Authoring GraphQL) are deferred — the schema risk is real, the bento story doesn't depend on them, and adopters can wire them themselves later.

## 3. Goals and Success Metrics

### Primary goals

- **G1 — Bento renders cleanly inside the Cloud Portal iframe**, with all 5 free cards live and accurate (real data flowing from the Marketplace SDK + Supabase). 11-card layout responsive from mobile (single-column stack) to desktop (full bento grid).
- **G2 — Premium gating is visually unambiguous.** A user who has not paid sees the 5 free cards plus a centered, prominently-styled "Unlock Premium — €0.99 lifetime" banner over 6 blurred premium card silhouettes. The blurred cards retain enough visual texture (chart shapes, grid lines) to communicate "this is real content you're missing", not "this is broken". **No real data fetches run in locked state** — premium cards mount as placeholder skeletons.
- **G3 — Unlock flow is delightful.** User clicks Subscribe → Stripe Checkout → returns → iframe reloads → premium cards stagger-in over ~600ms with chart-draw-in animations. No jarring layout shifts, no half-rendered states.
- **G4 — Free Sitecore data is real and reusable.** `xmc.sites.listSites` powers the free Sites card. Adopters can fork the query pattern and add their own. Premium tier intentionally fake to avoid scope creep on unknown Sitecore Authoring schemas.
- **G5 — Three-state theme support.** Light / dark / system theme works across the entire bento. Toggle visible in the topbar (showcase-only — adopters env-gate for production per ADR-0016). All charts re-render colors correctly on theme change.

#### Locked-state visuals + unlock animation

- **Blur mechanic** — premium cards rendered in DOM but with `filter: blur(12px)` + `opacity: 0.7` + `pointer-events: none`. In locked state, cards mount as placeholder shapes (skeleton silhouettes that resemble the eventual card structure but contain no real data). In AllowedState, cards mount with their fake-data content + animations.

- **Unlock animation** — when `useEntitlement` resolves to `allowed` and `window.location.reload()` fires, the reloaded page detects `AllowedState` and renders the premium cards with a **stagger-in cascade** in visual reading order:

  - Counter animations (numeric cards): `requestAnimationFrame` loop from 0 → final over ~600ms with ease-out.
- **No layout shift** — both locked + unlocked layouts use the same grid; only `filter`, `opacity`, `pointer-events`, and card content toggle.

## 6. User Stories

### US-1 — Unauthenticated tenant lands on the bento

**As a** tenant editor opening the paywall-blueprint Marketplace app in Cloud Portal for the first time (no subscription yet),
**I want** to see a dashboard that clearly shows what I get for free AND what I'd unlock with €0.99,
**So that** I understand the value before paying.

**Acceptance:**
- AC1.1 — On `/full-page` iframe load, 5 free cards render with real data within 2s of Marketplace SDK handshake.
- AC1.2 — Below the free row, the premium region renders with `filter: blur(12px)` + `opacity: 0.7` + `pointer-events: none`; 6 premium card silhouettes visible but unreadable.
- AC1.3 — A centered Subscribe banner overlays the blurred region with locked copy "Unlock Premium — €0.99 lifetime" + Subscribe button.
- AC1.4 — Each blurred card has a "Premium" badge in the corner.
- AC1.5 — A subtle shimmer animation runs across the blurred region (~3s loop, low opacity, suggests "there's content here").
- **AC1.6a** — `getByText(/tenant_no_subscription/i)` returns no match in DOM after bento has rendered.
- **AC1.6b** — Browser console has zero entries at log level `error` after initial render.

### US-2 — Free Sitecore data is real

**As a** tenant editor using the bento,
**I want** the Sites card to show real data from my actual tenant,
**So that** the dashboard feels live, not mocked.

**Acceptance:**
- AC2.1 — Sites tile shows the actual count returned by `xmc.sites.listSites`. If 0 sites: "No sites in this tenant yet — create one in XM Cloud to see it here."
- AC2.2 — Sites tile lists up to 2 site names (truncated with "…and N more" if there are more).
- AC2.3 — Extension points card shows chips for each entry in `application.context.extensionPoints[]`. Includes `xmc:fullscreen` at minimum.
- AC2.4 — If the SDK query fails (network blip, scope missing), the card falls back to a "Couldn't load" state with a small Retry link. Does not break the rest of the page.

### US-3 — User pays and the bento unblurs with a delightful animation

**As a** tenant editor clicking Subscribe,
**I want** the unlock to feel like a reward, not a page load,
**So that** the €0.99 spend feels worthwhile.

**Acceptance:**
- AC3.1 — Click Subscribe → existing `PaywallCheckoutDialog` opens → Stripe Checkout tab opens (PRD-001 flow unchanged).
- AC3.2 — Pay with `4242 4242 4242 4242` → Stripe redirects to `/paywall-return` → iframe receives postMessage OR polling detects status change.
- AC3.3 — `useEntitlement.resolveSuccess` fires `window.location.reload()` (PRD-001 visibility-refresh contract).
- AC3.4 — On the reloaded page, the gate evaluates to `allowed`; the AllowedState render path renders the bento WITHOUT the blur and WITHOUT the Subscribe banner.
- AC3.5 — Premium cards stagger-in over ~600ms with `@keyframes fadeUp` (translate + opacity), 80ms per-card delay in DOM/reading order.
- AC3.6 — Recharts chart in the activity card animates the area path on mount.
- AC3.7 — Numeric counter cards animate from 0 to final value over ~600ms.
- AC3.8 — Animation completion budget: design-target 1.5s; manual smoke check at Tranche D (not test-gated).

### US-4 — Premium tier feels rich without real backend data

**As a** tenant editor who has paid €0.99,
**I want** the premium cards to look impressive and useful,
**So that** the value of paying is visually apparent.

**Acceptance:**
- AC4.1 — Activity trends chart (P1) renders a believable 30-day pattern with peaks/dips (hardcoded or deterministically generated).
- AC4.2 — Content health card (P2) shows 3 animated progress bars with sensible labels and percentages.
- AC4.3 — Recent edits feed (P3) shows 5 static entries with relative-time strings ("2h ago", "yesterday").
- AC4.4 — Engagement metrics (P4) shows 4 stat tiles with counter animations on mount.
- AC4.5 — AI insights (P5) shows 3 bullet points with believable text.
- AC4.6 — Engagement score (P6) shows a progress ring + forecast sparkline.
- AC4.7 — **No card on the premium tier makes an HTTP request, runs a database query, or calls the Marketplace SDK.** Verified via Network panel inspection (manual smoke) and unit-test mocks (Tranche D).

### US-5 — Theme switching works on every card

**As a** tenant editor preferring dark mode,
**I want** to toggle theme from the topbar and have all bento cards re-render correctly,
**So that** the dashboard fits my environment.

**Acceptance:**
- AC5.1 — Topbar shows a theme toggle icon button (sun / moon / system) in `rightSideItems`.
- AC5.2 — Clicking the toggle opens a 3-option dropdown (Light / Dark / System); selection persists via next-themes (`localStorage` key `theme`).
- AC5.3 — Theme persists across page reloads.
- AC5.4 — All Blok semantic tokens (foreground, background, primary, muted, etc.) re-render correctly in both light + dark.
- AC5.5 — Recharts charts re-render with theme-appropriate stroke + fill colors (no hard-coded hex values).
- AC5.6 — Blurred-state remains visually coherent in both themes.
- AC5.7 — Initial theme defaults to `system` (matches OS preference).

## 7. Functional Requirements

### FR-1 — Bento composition

- **FR-1.1** — A new `<BentoGrid>` component at `site/components/bento/bento-grid.tsx` owns the layout shell. Replaces `<FreeSection>` + `<GatedSectionWithDevPicker>` in `app/full-page/page.tsx`.
- **FR-1.2** — `<BentoGrid>` renders a 2-row visual structure: row 1 = free cards; row 2 = premium cards (locked or unlocked depending on entitlement). Exact CSS grid template deferred to UI Designer per ui_variants=2.
- **FR-1.3** — Each card is a separate component (`<WelcomeHero>`, `<SitesTile>`, etc.) under `site/components/bento/`.
- **FR-1.4** — `<BentoGrid>` consumes the existing `useEntitlement` state to switch between locked (blurred + Subscribe banner + placeholder shapes) and unlocked (revealed with fake-data + animations). The bento is composed at `app/full-page/page.tsx` level, NOT inside `<NoSubscriptionState>` / `<AllowedState>`. Those legacy state components remain in the codebase as design-reference for `seats-full` / `unassigned` paths but are no longer rendered on `/full-page`. README "States" section updated.

### FR-2 — Free card data hookup

- **FR-2.1** — `<WelcomeHero>` reuses the existing `pickUserDisplay()` chain (host.user.given_name → name → email → "there") + `application.context.resourceAccess[0].tenantDisplayName`.
- **FR-2.2** — `<SitesTile>` calls `client.query('xmc.sites.listSites')` on mount via the Marketplace SDK. Loading state = Blok Skeleton; error state = "Couldn't load" + Retry; empty state = "No sites in this tenant yet — create one in XM Cloud to see it here."
- **FR-2.3** — `<PlanCard>` reads Supabase `tenants` row via existing `SupabaseStore.getEntitlement(tenantId, '')`. Shows plan + status + member since (formatted as "Member since May 17, 2026").
- **FR-2.4** — `<RecentActivity>` queries Supabase `processed_events` filtered by the new `tenant_id` column (ADR-0017) for the last 5 events. Server-rendered via the existing SupabaseStore pattern (no new API route). Shows event type + relative time. Empty state for fresh tenants (no events yet): "No activity yet — your first webhook event will appear here." Data fetched at page load only; no auto-refresh.
- **FR-2.5** — `<ExtensionPointsCard>` reads `application.context.extensionPoints[]` and renders one Blok Badge per entry.

### FR-3 — Premium card content (FAKE)

All 6 premium cards mount with hardcoded or deterministically-generated fake data. **No card runs an API fetch, database query, or SDK call at any point.** Per operator direction 2026-05-17 ("fake it till we make it"). Verified at Tranche D via Network panel smoke (AC4.7).

- **FR-3.1** — Locked-state: all 6 premium cards mount as placeholder shapes (skeleton silhouettes). No data, no animation. Just enough visual structure to show "there's content here".
- **FR-3.2** — Unlocked-state: each card mounts with its fake-data content + the stagger-in animation per FR-6.
- **FR-3.3** — `<ActivityChart>` (P1) — Recharts AreaChart with hardcoded 30-day daily counts (believable weekday/weekend pattern). Recharts lazy-loaded per NFR-1.
- **FR-3.4** — `<ContentHealth>` (P2) — 3 animated progress bars with labels: "SEO score" (87%), "Performance" (92%), "Accessibility" (78%).
- **FR-3.5** — `<RecentEdits>` (P3) — 5 static list entries with names + relative times. Hardcoded.
- **FR-3.6** — `<EngagementMetrics>` (P4) — 4 stat tiles with hardcoded final values + counter animations on mount: Page views 12,400 / Conversions 248 / Avg session "4m 32s" / Bounce rate 28%.
- **FR-3.7** — `<AIInsights>` (P5) — 3 hardcoded bullets. No fetch, no AI call. Examples:
  - "Your busiest day is typically Tuesday."
  - "Premium content drives 3.2× engagement."
  - "Consider scheduling around peak windows."
- **FR-3.8** — `<EngagementScore>` (P6) — progress ring with hardcoded value (87/100) + dashed-line forecast sparkline (hardcoded data).

### FR-4 — Theme toggle

- **FR-4.1** — A new `<ThemeToggle>` component at `site/components/theme-toggle.tsx`. Renders a button (sun / moon / monitor icon depending on current theme) that opens a 3-option dropdown (Light / Dark / System).
- **FR-4.2** — Uses `next-themes` `useTheme()` hook. Already a dep (verify in PRD-002 Tranche A).
- **FR-4.3** — Mounted in the Topbar's `rightSideItems[]` slot. Always visible (showcase posture; departs from `feedback_dark_mode_default_policy.md` env-gating per ADR-0016 — adopters env-gate for production).
- **FR-4.4** — `<ThemeProvider>` from next-themes wraps the app at root layout (verify in Tranche A; install if missing).
- **FR-4.5** — Theme persistence via next-themes defaults (`localStorage` key `theme`).
- **FR-4.6** — All bento cards use Blok semantic tokens (`bg-background`, `text-foreground`, `border-border`, etc.) — NO hard-coded hex values that don't theme. Enforced by `test:no-hex-in-bento` regex test (Tranche A).

### FR-5 — Unlock animation

- **FR-5.1** — Premium cards in AllowedState render with a CSS class `bento-card--premium` that has `animation: fadeUp 600ms ease-out forwards` and `animation-delay` set per-card.
- **FR-5.2** — Stagger-in delays follow **DOM order**, which **MUST match visual reading order** (top-left → right → next row → top-left → right) — 0ms, 80ms, 160ms, 240ms, 320ms, 400ms. UI Designer's chosen variant must preserve this constraint.
- **FR-5.3** — `@keyframes fadeUp { from { opacity: 0; transform: translateY(16px); } to { opacity: 1; transform: translateY(0); } }`.
- **FR-5.4** — Recharts components use `isAnimationActive={true}` (default) for path draw-in.
- **FR-5.5** — Numeric counter cards animate from 0 to final value via `requestAnimationFrame` loop over 600ms with ease-out interpolation.
- **FR-5.6** — Animations respect `prefers-reduced-motion: reduce` — if set, all animations skip directly to final state.
- **FR-5.7** — No animation runs on LockedState premium cards (they're static placeholder silhouettes).

### FR-6 — Blur + Subscribe banner

- **FR-6.1** — Locked-state premium region: a wrapper `<div className="premium-region--locked">` with `filter: blur(12px)` + `opacity: 0.7` + `pointer-events: none`. Children = the 6 premium card placeholder components. **Tranche C smoke includes a manual readability check** — text content must be unreadable from 50cm at typical viewport zoom.
- **FR-6.2** — Above the locked premium region, an absolute-positioned Subscribe banner: card-like Blok component with primary-color glow, centered title "Unlock Premium — €0.99 lifetime", subtitle "One-time payment. Lifetime access. No subscription.", primary button "Subscribe — €0.99 lifetime" that opens `<PaywallCheckoutDialog>`.
- **FR-6.3** — Shimmer animation across the locked region: CSS `@keyframes shimmer` on the wrapper using a translucent gradient that slowly translates left-to-right over ~3s loop. Subtle (low opacity); communicates "content here".
- **FR-6.4** — When AllowedState: the wrapper drops the `--locked` class, blur/opacity/pointer-events restored, banner unmounts.
- **FR-6.5** — Locked premium region has `aria-hidden="true"`; screen readers skip it. The Subscribe banner is the only interactive element in the locked state.

### FR-7 — Card error states (free cards only — premium cards have no errors)

- **FR-7.1** — Every free card component handles its own loading + empty + error state independently. One failed card never blanks the whole bento.

## 8. Non-Functional Requirements

- **NFR-1 — Bundle size budget.** **Recharts is NOT currently installed** — Tranche A `npm install recharts` is required. Recharts is **lazy-loaded via dynamic import** (`const ActivityChart = lazy(() => import('./activity-chart'))`) so the free-tier render path doesn't pay the bundle cost. **Budget:** free-tier chunk delta ≤ 50kb gzipped. Premium-only chunks (Recharts + premium card components) load on AllowedState; not counted against the budget.
- **NFR-2 — Accessibility.** All cards have semantic structure (headings, regions). All interactive elements (buttons, links) keyboard-reachable with visible focus rings. Color contrast meets WCAG AA in both light + dark themes. The locked premium region is `aria-hidden="true"` so screen readers skip it (only the Subscribe banner is interactive in locked state).
- **NFR-3 — Performance.** Initial bento render (free cards) ≤ 2s after Marketplace SDK handshake. `xmc.sites.listSites` ≤ 3s before fallback message. No layout shift (CLS) > 0.1.
- **NFR-4 — Responsive.** Desktop (≥1024px) renders the full bento. Tablet (768–1024px) collapses to 2-column grid. Mobile (<768px) collapses to single-column stack with all 11 cards visible. No horizontal scroll at any breakpoint.
- **NFR-5 — Reduced motion.** `prefers-reduced-motion: reduce` skips all stagger-in / shimmer / chart-draw / counter animations. State changes are still applied; only the animated transitions are skipped.
- **NFR-6 — Theme contrast.** Every card text/background combo passes WCAG AA in both light + dark. Manual smoke check at Tranche D.
- **NFR-7 — Auth posture for new data path.** F4's Supabase query runs server-side via the existing `SupabaseStore` pattern (RSC fetch in the F4 component). Same auth posture as PRD-000 — service-role key, no per-request auth in v1.
- **NFR-8 — Server-only env vars.** `STRIPE_SECRET_KEY`, `SUPABASE_SECRET_KEY` continue to be server-only. Existing `npm run test:env-leak` covers this.
- **NFR-9 — No hex colors in bento.** New `test:no-hex-in-bento` script: regex check that no `#[0-9a-fA-F]{3,8}` literal appears in `site/components/bento/**` or `site/components/theme-toggle.tsx`. Ensures all colors use Blok semantic tokens; both themes render correctly. Added at Tranche A.
- **NFR-10 — Library structure for adopter forks.** Each bento card is a separate component file in `site/components/bento/`. Cards accept data via typed props (no fetches inside the card body — fetches live in the layout shell or via server-render). The `<BentoGrid>` shell is the single place that wires data to cards. README "Customizing the bento" subsection (Tranche E) documents the swap pattern with a concrete code example.

## 13. Risks and Mitigations

### R1 — Cloud Portal app registration lacks `xmc.sites.*` scope

**Risk:** `xmc.sites.listSites` fails with permission-denied envelope at Tranche A. F2 ships with "Couldn't load" state; Sitecore-data story collapses to just the extension-points card.

**Mitigation:** Operator pre-flight at Tranche A verifies the scope in Cloud Portal → App Studio. If scope unavailable / named differently / requires approval, capture the actual scope name and update the PRD before Tranche A code work. Fallback: F2 ships with documented "Not available — see README" state. README adds a Sitecore-app-registration prerequisites section.

### R2 — `xmc.sites.listSites` response shape differs from skill docs

**Risk:** Skill-documented shape doesn't match real tenant response. F2 card crashes or shows wrong data.

**Mitigation:** Progressive-fixture-capture per `feedback_assumed_shapes_progressive_capture.md`. Tranche A real-tenant smoke captures the actual shape; component adjusted inline if differs. Failure mode is bounded to one card.

### R3 — Bento layout doesn't translate cleanly to mobile

**Risk:** Grid collapses awkwardly on mobile (cards out of order, weird sizing).

**Mitigation:** UI Designer designs mobile-first with collapse rules per variant. Tranche B testing includes a manual responsive smoke. The mobile layout is single-column-stack as a fallback (NFR-4).

### R4 — Animation budget exceeded on slow devices

**Risk:** Stagger-in + chart draw-in + counter animations + shimmer + progress-bar fill = visual jank on low-end hardware.

**Mitigation:** All animations CSS-based (GPU-accelerated). Recharts isAnimationActive can be disabled per-component if profiling shows issues. `prefers-reduced-motion` fallback ensures users on low-end devices opt out.

### R5a — Premium content structurally leaks through the blur (blueprint posture)

**Risk:** Browsers might allow text selection or screen readers might read through `pointer-events: none` and `filter: blur(12px)`. Premium DOM technically present.

**Mitigation (blueprint posture):** Locked-state cards mount as placeholder silhouettes only — NO fake data, NO real data, no fetches (FR-3.1). The "shape leak" is intentional (skeleton silhouettes communicate "there's a card here"). The premium region also gets `aria-hidden="true"` (NFR-2). No actual content is exposed through the blur because there's no content to expose in locked state.

### R5b — Adopters who add real premium data must harden the gating

**Risk:** Adopters forking paywall-blueprint and replacing the fake premium cards with REAL data signals (the natural next step for production use) inherit the blueprint's "render premium in DOM" posture. Real premium content becomes visible in DOM (just visually blurred), enabling client-side gate bypass.

**Mitigation:** README "Production hardening for adopters" section explicitly warns: when adopters replace fake premium data with real fetches, they MUST gate the fetches server-side via the existing `/api/entitlement` check OR via a `withEntitlement(handler)` HOF (future PRD candidate). The blueprint's "render then blur" posture is showcase-only; production deployments need server-side enforcement.

### R6 — Theme toggle conflicts with existing color setups

**Risk:** Some existing components in the app (PaywallCheckoutDialog, dev affordances) use hard-coded colors that don't theme. Toggle reveals visual bugs.

**Mitigation:** `test:no-hex-in-bento` covers the bento. Tranche B + D manual visual smoke in both themes catches cross-component issues. Fix as found.

### R7 — Theme toggle policy departure surprises adopters

**Risk:** Adopters who read `feedback_dark_mode_default_policy.md` expect the env-flag pattern; PRD-002's always-visible toggle confuses them.

**Mitigation:** ADR-0016 explicitly names the departure as showcase-only. README "Production hardening" section reminds adopters to env-gate for production. The decision is auditable.

### R8 — Recharts bundle size impact on cold-load

**Risk:** Even lazy-loaded, Recharts adds ~80–100kb gzipped to the premium chunk. AllowedState first-load adds latency.

**Mitigation:** Acceptable trade-off for the showcase. The free-tier first paint is unaffected (Recharts not loaded). AllowedState reload triggers the chunk fetch; perceived as part of the "unlock celebration" moment. If profiling shows issues, swap Recharts for a lighter chart lib (Visx, native SVG, or pure CSS bars).
