## 1. Design context & assumptions

### Audience

- **Primary:** OSS blueprint adopters reading paywall-blueprint as a forkable showcase. They land on `/full-page` inside the Cloud Portal iframe (or via direct Vercel URL) and decide in seconds whether the pattern is worth copying.
- **Secondary:** tenant admins running paywall-blueprint as a reference deployment, evaluating the €0.99 unlock.

Both audiences see the same surface; both judge "is this app polished enough to keep / fork" inside the first 3 seconds.

### Goals and success criteria

- G1 — Bento renders inside the Cloud Portal iframe (Full Screen extension point — 1024–1920px wide, 600–1080px tall) without horizontal scroll at any viewport.
- G2 — Premium gating is visually unambiguous; the locked region looks intentional (not broken).
- G3 — Unlock animation feels celebratory; CSS keyframes + Recharts built-ins; ≤1.5s end-to-end.
- G4 — Real Sitecore data (`xmc.sites.listSites` + `application.context`) sits in the free tier.
- G5 — Three-state theme (light / dark / system) works on every card.
- G6 — Ship gate: `test:no-hex-in-bento` green (no hex literals in `site/components/bento/**` or `site/components/theme-toggle.tsx`).

### Constraints (brand, a11y, stack)

- **Stack** locked: Blok primitives via shadcn registry, Tailwind v4 / Nova preset (CSS-first tokens in `@theme inline { … }`), `next-themes` for theming, `recharts` (lazy-loaded), `lucide-react` for icons. NO `framer-motion` / `motion` / `lottie`.
- **Brand** locked: Sitecore Blok semantic tokens only. No hex literals. No custom font families beyond the Geist Sans / Geist Mono pair that the Nova preset already loads.
- **A11y** locked: WCAG AA contrast in both themes; keyboard-reachable interactive elements with visible focus rings; locked premium region `aria-hidden="true"`; `prefers-reduced-motion: reduce` honored.
- **Iframe** locked: Full Screen extension point; shadows must stay small (`shadow-sm` / `shadow`) per `sitecore:blok-marketplace-integration` skill — large shadows clip at iframe edges.
- **DOM order = visual reading order** (FR-5.2) for the stagger-in cascade.

### Reference / inspiration

- **Linear's dashboard density** — peer cards in a strict grid; the value is in the data, not in card chrome
- **Stripe Dashboard's free-tier overview** — uniform card sizing with restrained accent treatment
- **Vercel dashboard's "calm" mode** — neutral backgrounds, accent only where action is needed
- **PRD-000 POC reference** at `products/paywall-blueprint/pocs/poc-v1-prd000/` — visual continuity baseline (same Topbar, same primary-accent treatment for Subscribe CTA)

This variant rejects "bento-as-magazine-layout" (the asymmetric masonry path is v2's territory). v1 commits to the dashboard-grid lineage: every card is a peer, the rhythm is the point, and prominence comes from interrupting the rhythm only when something demands attention (the Subscribe banner spanning a full row).

## 2. Design direction

### Direction name: **Mosaic Discipline**

Eleven cards. One grid. One rhythm.

### Visual direction

**Mosaic Discipline** treats the bento as a disciplined mosaic of equal voices — every card is a peer, every gap is a rest, every accent is earned. The aesthetic anchor is the Sitecore Blok base surface (deep neutrals, restrained chroma, generous interior padding, micro-shadows) rendered as a strict 3-column tessellation. Nothing dominates by size; prominence is reserved for the Subscribe banner, which earns its weight by **breaking the grid horizontally** — spanning the full 3-column row in locked state instead of by being visually larger.

Typography is dense and confident. Card titles sit in `font-medium text-foreground` at the same scale across every tile; supporting metadata in `text-muted-foreground`; KPI numbers in `font-mono` for that "data viz" anchor. Borders are 1px in `border-border`, radii are the Blok default `rounded-lg`, shadows are `shadow-sm` only (iframe-safe per `blok-marketplace-integration`). The accent (`--primary`) shows up exactly four places: the plan badge (F1, F3), the Subscribe banner ring + CTA, the Premium corner badges, and the Activity chart area-fill. Everywhere else: neutral.

In dark mode the discipline gets richer — `bg-card` becomes a near-black with a hint of warmth; borders soften to `border-border/60`; the primary accent gains a subtle outer glow on the Subscribe banner only. Both themes feel polished without competing for attention with the chart and KPI content they exist to frame.

### Layout and structure

A **3-column × 4-row fixed grid** at desktop. Every card is 1 column × 1 row except the Subscribe banner in locked state (which spans all 3 columns × 2 rows over rows 3–4, replacing the premium grid). Row gap = column gap = the Blok `spacing-4` token (≈16px). The grid lives inside a `max-w-7xl mx-auto px-6 py-8` shell so the iframe always has breathing room at the edges.

```
┌─────────────────────┬─────────────────────┬─────────────────────┐
│  Row 1 (free)       │                     │                     │
│  F1 Welcome hero    │  F2 Sites tile      │  F3 Plan + member   │
├─────────────────────┼─────────────────────┼─────────────────────┤
│  Row 2 (free)       │                     │                     │
│  F4 Webhook         │  F5 Extension       │  (spacer in         │
│     activity        │     points          │   unlocked state    │
│                     │                     │   OR locked-state   │
│                     │                     │   Subscribe banner  │
│                     │                     │   starts here)      │
├─────────────────────┴─────────────────────┴─────────────────────┤
│  Row 3 + 4 (premium)                                             │
│  LOCKED: Subscribe banner spans full width, rows 3–4              │
│          (6 premium placeholder silhouettes blurred beneath)      │
│  UNLOCKED:                                                        │
│  ┌──────────────────┬──────────────────┬──────────────────┐    │
│  │ P1 Activity      │ P2 Content       │ P3 Recent edits  │    │
│  │    chart         │    health         │                  │    │
│  ├──────────────────┼──────────────────┼──────────────────┤    │
│  │ P4 Engagement    │ P5 AI insights   │ P6 Engagement    │    │
│  │    metrics       │                  │    score         │    │
│  └──────────────────┴──────────────────┴──────────────────┘    │
└─────────────────────────────────────────────────────────────────┘
```

The free row (rows 1–2) renders unconditionally. The premium region (rows 3–4) switches its inner composition based on `useEntitlement.status`:

- **`tenant_no_subscription`** (locked) — 6 premium placeholder silhouettes occupy a 3×2 sub-grid; the wrapper has `filter: blur(12px) opacity(0.7) pointer-events:none aria-hidden="true"`; an absolute-positioned `<SubscribeBanner>` overlays the region (`grid-row: 3 / span 2; grid-column: 1 / -1`).
- **`allowed`** (unlocked) — 6 premium cards in a 3×2 sub-grid stagger in over ~600ms.

**No layout shift between states** (FR-6.4) — the wrapper occupies the same grid area in both states. The Subscribe banner's full-row span IS its prominence; nothing about the grid template changes.

The spacer in row 2, column 3, unlocked state: an empty grid cell. The bento intentionally leaves this slot open in unlocked state — symmetric to the locked state's Subscribe banner stem and visually communicating "row 2 is the free tier ending; row 3 begins the premium tier." This is a deliberate v1 choice: rather than cramming a 6th free card to fill the grid, the negative space is a rest beat in the rhythm. (See § 7-F-spacer for the alternative if operator vetoes.)

### Key components and patterns

- **Card** (`@blok/card`) — uniform surface for all 11 tiles. `bg-card border border-border rounded-lg shadow-sm p-6`.
- **Topbar** (`@blok/topbar` — already installed) — extended with `<ThemeToggle>` in `rightSideItems[]` per ADR-0016.
- **Subscribe banner** — composed primitive: Card with `ring-2 ring-primary shadow-md` + centered content stack (title / subtitle / CTA `@blok/button` `variant="default"`).
- **Premium corner badge** — `@blok/badge colorScheme="primary"` absolute-positioned top-right of each placeholder silhouette in locked state; carries the text "Premium".
- **Stagger-in cascade** — CSS `@keyframes fadeUp` with `nth-child` delay rules; DOM order = reading order (top-left → right → next row → top-left → right).

## 3. Key screens and flows

### Screens

`/full-page` is the only screen this PRD adds — but it has **three visual modes** the design must spec:

1. **Locked-state bento** (entitlement = `tenant_no_subscription`, the default state for new tenants)
2. **Unlocked-state bento** (entitlement = `allowed`, post-payment)
3. **Loading / handshake state** (Marketplace SDK still resolving) — free cards render Blok Skeleton silhouettes; premium region renders the locked-state silhouettes (no flicker)

### Critical user flows

**Flow A — First-visit, no subscription (the most common path the bento is built for):**

1. Iframe loads `/full-page` → `<ThemeProvider>` mounts → `<MarketplaceProvider>` initiates handshake
2. Skeleton state: 11 silhouettes in the bento grid (free + premium both Blok skeletons)
3. SDK handshake completes (100–500ms typical per blok-marketplace-integration § 4) → free cards mount with real data
4. `useEntitlement` resolves to `tenant_no_subscription` → premium region adopts `.premium-region--locked` wrapper class → 6 placeholder silhouettes render blurred
5. `<SubscribeBanner>` overlays rows 3–4 → primary CTA visible and focused-on by keyboard tab from Topbar
6. User clicks Subscribe → existing `<PaywallCheckoutDialog>` opens (PRD-001 flow, unchanged)
7. Stripe Checkout completes → `/paywall-return` → iframe reload → flow B

**Flow B — Post-payment unlock celebration:**

1. Page reloads → `useEntitlement` resolves to `allowed`
2. Free cards render immediately (unchanged from flow A step 3)
3. Premium region renders WITHOUT `--locked` class → Subscribe banner unmounts
4. 6 premium cards mount with fake data + `bento-card--premium` class → CSS stagger-in cascade fires (0ms / 80ms / 160ms / 240ms / 320ms / 400ms)
5. P1's Recharts `<AreaChart>` animates its path on mount (Recharts built-in `isAnimationActive={true}`)
6. P4's counter animations tick 0 → final value over 600ms (`requestAnimationFrame` ease-out)
7. P2's progress bars animate fill 0 → target % over 600ms
8. P6's progress ring + sparkline animate on mount
9. End state: bento fully populated; total animation budget ≈1.5s; respects `prefers-reduced-motion: reduce`

**Flow C — Theme switch:**

1. User clicks `<ThemeToggle>` in topbar → `@blok/dropdown-menu` opens with 3 options (Light / Dark / System)
2. User selects → `next-themes` flips `.dark` class on `<html>` → all Blok semantic tokens reflow
3. Recharts re-renders with theme-derived stroke/fill (via `useTheme()` passing `hsl(var(--primary))` strings — AC5.5)
4. Locked-state shimmer overlay (which uses `hsl(var(--muted) / 0.12)`) stays coherent
5. No page reload; no layout shift

### Responsiveness

| Breakpoint | Grid template | Notes |
|---|---|---|
| Desktop ≥1024px | `grid-template-columns: repeat(3, minmax(0, 1fr))` | Full 3×4 bento; Subscribe banner spans 3 cols when locked |
| Tablet 768–1024px | `grid-template-columns: repeat(2, minmax(0, 1fr))` | 2-column collapse: F1+F2 / F3+F4 / F5+spacer / locked banner spans 2 OR unlocked premium 3×2 becomes 2×3 |
| Mobile <768px | `grid-template-columns: minmax(0, 1fr)` | Single-column stack; Subscribe banner spans 1 col; all 11 cards visible by scroll |

Critical: `minmax(0, 1fr)` on every column to prevent grid-item escape from track when content has unbreakable tokens (the CSS Grid min-width trap captured in `reference_css_grid_min_width_trap.md`). Also card content uses `min-width: 0; max-width: 100%; overflow-wrap: anywhere;` on the inner text wrapper.

### Accessibility notes

- **Topbar's `<ThemeToggle>`:** `<button aria-label="Toggle theme">` triggering `@blok/dropdown-menu`; menu items have visible text labels ("Light" / "Dark" / "System") + lucide icons that inherit `currentColor`.
- **Free cards:** every card is a `<section aria-labelledby="card-X-title">` with a hidden `<h2>` for the card name. List items in F4 use `<ul>`/`<li>`. Stat tiles in P4 use `<dl>`/`<dt>`/`<dd>` (when unlocked).
- **Locked premium region:** wrapper `<div role="region" aria-hidden="true">` — screen readers skip the entire silhouette grid. The only interactive element in locked state is the `<SubscribeBanner>`'s Subscribe button (aria-label "Subscribe to premium for €0.99 lifetime"); it sits as a SIBLING to the locked wrapper, not inside it, so it remains discoverable by tab order.
- **Keyboard focus order in locked state:** Topbar items → F1 → F2 (Retry link if error) → F3 → F4 → F5 → [Subscribe banner CTA] → end.
- **Keyboard focus order in unlocked state:** Topbar items → F1 → F2 → F3 → F4 → F5 → P1–P6 (premium cards are non-interactive; they're skipped unless they contain a focusable element, which none do in v1). The unlocked premium region has no focusable elements — cards are display-only per PRD § 5 (no expand / drill-into).
- **Focus rings:** Blok semantic `ring-2 ring-ring ring-offset-2 ring-offset-background` on every focusable element. Visible in both themes.
- **Color contrast:** every text/background pair passes WCAG AA in both light + dark — verified at Tranche D smoke (NFR-6).
- **Reduced motion:** `@media (prefers-reduced-motion: reduce)` disables stagger-in, shimmer, counter, progress-fill, ring-fill, sparkline-draw, and Recharts `isAnimationActive={false}` (set conditionally based on `useReducedMotion()` hook or CSS `@media` matching).

| Surface | Token | Light theme appearance | Dark theme appearance |

**Specific token usage call-outs (for `test:no-hex-in-bento` reviewer):**

- Card background: `bg-card` (NEVER `bg-white` / `bg-slate-50` / `#fff`)
- Card border: `border-border` (NEVER `border-gray-200`)
- Card text: `text-foreground` (NEVER `text-black`)
- Muted text: `text-muted-foreground` (NEVER `text-gray-500`)

### Spacing scale — Blok defaults

| Token | Value | Use |
|---|---|---|
| `gap-4` | spacing-4 (≈16px) | Grid gap (between cards) |
| `p-6` | spacing-6 (≈24px) | Card interior padding |
| `space-y-3` | spacing-3 (≈12px) | Vertical rhythm inside cards |
| `space-y-2` | spacing-2 (≈8px) | Tight vertical rhythm (e.g., between icon-label and content) |

| `gap-2` | spacing-2 (≈8px) | Inline gap (e.g., F5 chip wrap, P4 tile sub-grid) |

The grid gap (`gap-4`) intentionally matches the visual "rest" between rhythm beats in the mosaic. Larger gaps (`gap-6+`) would feel airy / magazine; smaller (`gap-2`) would feel cramped. `gap-4` is the discipline.

## 11. Responsiveness and accessibility — summary

### Responsive

- **Desktop ≥1024px** — 3×4 bento; canonical form
- **Tablet 768–1024px** — 2-column collapse; DOM order preserved
- **Mobile <768px** — single-column stack; spacer cell hidden; banner full-width

### Accessibility

- WCAG AA contrast in both themes (verified at Tranche D)
- Keyboard-reachable: Topbar items → 5 free cards (Retry links focusable) → Subscribe banner CTA (locked) OR premium cards (unlocked, but no focusable elements)
- Focus rings: `ring-2 ring-ring ring-offset-2 ring-offset-background` visible in both themes
- Locked premium region: `aria-hidden="true"` wrapper; Subscribe banner is SIBLING (not inside the hidden wrapper) so it remains discoverable
- Semantic HTML: each card is `<section aria-labelledby="card-N-title">` with hidden `<h2>`; F4 list uses `<ul>`/`<li>`; P4 stats use `<dl>`
- `prefers-reduced-motion: reduce`: disables all CSS keyframes, Recharts `isAnimationActive={false}`, counter animations skip to final value
- ARIA on ThemeToggle: `aria-label="Toggle theme"`; menu items have explicit text labels
- Screen reader on locked state: announces 5 free cards → Subscribe banner ("Unlock Premium — €0.99 lifetime, Subscribe button") → skips silhouette region entirely
- Color is never the sole differentiator: plan badges have text ("Free" / "Premium"), not just color
